# 招聘流程（实习 / 全职）

AI帮忙看资料、聊关键问题、整理给HR；HR和用人负责人决定面试及录用。具体流程见 [流程图](recruiting-flowchart.md)，常见说法见 [58场景语料模板](hr-corpus-template.md)。

## 先确认岗位

运行前，Agent先检查当前机器的REA、lark-cli和飞书skills，缺少时按授权补齐部署。同步人才库需要用户身份的飞书授权；没有有效登录态时，由Agent展示链接和二维码，用户用飞书扫码确认，Agent继续完成登录并核验目标人才库。机器人可用不等于用户已登录。已有有效授权则直接复用，不要求重复扫码。

HR先确认岗位类型、实际职责、工作地点和方式、预算及必须条件。全职月薪和实习日薪分别填写；模板里的100–120元/天及15–25K/月是示例，不是其他岗位的待遇承诺。

## 看资料，再聊两轮

AI结合当前简历、附件和已有聊天，记录“已确认”“候选人自述”“还不清楚”，已经说过的不再问。简历资料卡、在线摘要和PDF分开看，读取不到的内容不补写。

| 沟通 | 实习 | 全职 |
|---|---|---|
| 第一轮 | 代表项目、本人的工作和实际成果；开发岗按需问AI代码如何检查 | 相关经历、独立负责范围与实际交付；围绕岗位补关键能力证据 |
| 第二轮 | 日薪、地点、每周出勤、实习月数、学校手续、到岗日 | 期望月薪、在职状态、交接周期、地点/办公方式、职级方向、入职日 |

每次抓关键问题，最多两轮实质沟通。两轮后还有缺口，就整理交HR，避免持续盘问。候选人有其他offer时，按需确认其决策截止时间，不让对方拒掉其他机会来等我们。

## 先初筛，再交接

初筛通过的，写入飞书当前岗位人才库，HR状态保持待复核；信息不足或条件冲突的先交人工判断，不能伪装成通过。评分只是辅助，不能代替真人决定，更不能自动拒绝。

表里整理岗位、薪资、姓名、院校、能力与岗位匹配证据、最近联系时间、最快到岗日、简历链接和待确认项。已有的人口信息只据实记录、不推断，不作为与岗位无关的评分依据。院校分类和能力评价分开。

入库并完成实际交接后，才能告诉候选人“简历和沟通情况已整理给招聘团队复核”。后续渠道、时间和结果按真实状态同步，不保证面试、offer或邮件必达。

HR看表后选择面试、暂缓或不推进。面试官与用人负责人给出结果，HR按批准内容发正式通知。当前岗位不合适而希望后续保留资料的，先征得同意、另标用途，不写成当前岗位初筛通过；候选人退出则停止后续联系并处理资料请求。

## HR如何教AI说人话

在语料模板中找到相应岗位类型和场景，把自然说法填进“HR实际说法”，核对事实与承诺后改为“启用”。待确认、停用或实际说法为空的条目不能视为批准口径。没有启用语料时，AI先出待审草稿。

AI参考语气和结构，每次仍要核对本人的事实；这不是模型自动训练，也不把每一条已发送消息自动写成通用话术。

## 多个Agent怎么分工

每个人的材料可以交不同subagent研究，主Agent统一检查和执行。发消息时排队，每次只发一人；发前核对身份和最新聊天，发后回读确认唯一新增记录。结果不明先检查，不换脚本重发。

本仓库的技术skill负责接口，招聘skill负责上述流程。Mac 与 Windows 均只验证了具体技术能力，边界见根目录验证报告；完整招聘流程与飞书交接未验证。复制流程文档不会自动获得候选人发送授权。
