# HR 沟通语料库模板

这是一张给 HR 填空、也给 Agent 检索参考的语料库。语料按“岗位类型”区分：实习、全职或通用。初始内容只是待审草稿，HR 确认并改成“启用”后，Agent 才会参考。

示例中的地点、日薪、出勤和周期仅用于填写演示；每个岗位的真实条件须单独核验。全部建议话术均为待 HR 确认草稿。

## 怎么用

1. 先按“岗位类型”和“场景分类”找到最接近的一行。
2. 看“AI建议话术”，把花括号里的内容换成真实信息。
3. 把最终准备发出的自然表达填进“HR实际说法”。
4. 确认没有过度承诺、没有使用无关个人信息，再把“审核状态”改成“启用”。
5. AI 下次起草时优先参考“启用”的 HR实际说法；没有把握的继续转人工。

## 实习和全职的关键区别

- 实习重点确认：学校安排、每周到岗天数、最少实习月数、学校手续、最快到岗日期。
- 全职重点确认：当前在职/离职状态、离职交接周期、月薪期望、工作地点、职级方向、入职时间、offer 和其他机会的决策时限。
- 两类都先说真实情况：不承诺面试、offer、调薪或邮件必达。

## 对话规则

- 一次只解决一个问题，不把五六个问题塞在一起。
- 先说结论，再说原因和下一步。
- 能说具体时间就说，不能保证就不要编。
- 不说“高度匹配”“恭喜通过初筛”“肯定有面试”“最终一定邮件通知”等未经验证的结果。
- 不用年龄、性别、籍贯、婚育等与岗位无关的信息评价候选人。
- 候选人说停止联系或删除资料时，先执行，再回复。

## 给 Agent 的学习规则

- 先按岗位类型筛选：实习岗只查“实习+通用”，全职岗只查“全职+通用”。
- 再按场景、轮次和渠道筛选，优先使用最近且已启用的 HR实际说法。
- 只检索“审核状态=启用”的记录；待确认记录只能当草稿。
- HR实际说法为空时，AI不能假装已经学会，也不能把建议话术当成批准话术。
- 语料是参考，不是固定模板；候选人情况变了就重新判断，不机械照抄。
