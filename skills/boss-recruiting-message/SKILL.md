# BOSS沟通与发送验收

先读[公共契约](../boss-recruiting-followup/references/common-contract.md)；通过[实现映射](../boss-recruiting-followup/references/implementation-map.md)定位统一sender。输入是本人主验草稿、正式record/CAS、原始证据和明确的本条目的；离线review本身不等于发送许可。

## 本条是否可发

当前岗位按[Go转向规则](../boss-recruiting-followup/references/go-transition.md)，在剩余实质轮次内核清是否愿意转Go，可接受从零学习；已有答案不重问，不加第三轮。

每次草拟回复前，读取配置中的实时飞书HR沟通语料表，核对 `HR实际说法`、岗位类型、场景、适用轮次、审核状态、使用权限和审核备注，并在私有提案记录读取来源及所参考行。不能用本地模板或以前批次缓存代替本次检索。仅按已批准权限参考；待HR确认内容不能自行升级为已启用政策。语料只借鉴自然表达，薪资、时间、福利与流程须另核当前岗位已确认事实。没有匹配或读取失败时明确留证，不冒称已参考；必要回复依现有授权与已确认事实主验。实现见[HR语料引用](../boss-recruiting-agent/references/hr-corpus.md)。

- 存在真实未处理问题、合法缺项或已核验入库后交接才发；已问待答、感谢/确认和旧收尾不机械补发。最多两轮实质筛问，R2仅问缺项，不再问已有技术/工具/独立范围。
- R1后候选人以主动附件简历作答时，已接收、本人身份绑定且已读正文可作为R2回复证据，不要求其再发一条文字。提案须绑定完整历史中的本人已同意请求和后续实际附件送达事件、原件/正文SHA及正文精确引文；只有请求卡、未读正文或身份未绑定不能通过。最后实际出站锚点、真实轮次、数值门槛及其余发送校验保持不变；正文也不自动证明六项现实条件接受。
- R0澄清需真实round0和当前scope已授权验收策略；next_round=0不问新实质问题。政策和HR通知保持原实质轮次，不伪造round0；HR通知不计新增筛问。
- 本人首次主动询问能否发送简历时（包括“需要发一份简历看看嘛”等同义问句），即使基础全null，也可仅答“可以，直接在BOSS上发就行。”。须完整历史无招聘者文字出站、引用最新本人许可问句、真实round0、保持skipped_unknown_base/skip/next_round=0和整份score不变；仍经提案校验、统一sender及独立读回。否定或已发送的陈述不算许可问句。不得夹带技术问题、重新联系明确暂停/停联者或视为已接收简历。未知基础的首轮筛问和入库门槛不因此放宽。
- 人工接续、停联、疑似重复暂停及blocked项尊重原状态，不自动恢复。HR通知必须绑定真实Base逐字段读回成功，不能先发“已提交”再写库。
- 自然短句，一条一个主要目的，顺着对方问题回应；不机械“好的了解了”、ok、表情或提前“整理确认”。不索要简历、站外联系方式或验证代码，不承诺面试/offer/福利/转正。未知公司政策如实说未确认，不拿候选技术栈当公司栈。
- 工时只岗位事实，除非用户另有限制，不用作回复窗口。已授权必要步骤直接接续，不逐人请示。
- 用户限定业务披露范围时，按实时已确认语料只答允许的业务方向和说明时点，不补充或推测其他业务细节，也不把部门口径扩展为公司通用事实。
- 本人提到用过Claude Code且接入方式未明时，在剩余实质轮次内优先自然问“你用Claude Code是走中转站，还是用自己的账号？”。已明确的不重问，不索账号或凭据，不借此第三轮或补问已HR者；加分证据规则见[Claude Code账号追问](../boss-recruiting-followup/references/claude-code-account.md)。
- 先辨认聊天语境。对“这么晚还回消息，是不是经常加班”这类由回复时间引出的打趣，按用户偏好自然接“碰巧看见消息，就回一下。”，不机械拼作息或“加班未确认”。若对方进一步认真询问加班制度，再按已确认事实回答；不据回复时间推断加班，也不承诺不加班。旧消息不因改口吻补发。

## 每一条的真实执行

自然度校验只提示套话、过长、多目的，不自动改写或要求统一开头；主代理仍按本人上下文定稿，不为提速发送无内容确认。连接优化不删两次严格发前检查或独立新增回读，不另造发送入口。

1. 查锁和对应活跃进程，核runner当前scope/授权/源码SHA及所有未完成attempt。核job+UID+姓名/profile，实际UTF8正文SHA与正式record CAS。
2. 新鲜完整history与已审批证据一致，做双重严格发前校验；出现新入站先停本条重审，不把旧审批套到新事实。
3. 独占attempt，统一scripts/boss.mjs send只调用一次，保存approval/pre-send/SDK/result实际证据。不换入口或循环调用sender。
4. 独立完整回读，验证只有一条符合正文SHA的新增出站、无其他意外出站；CAS登记真实mid、history、轮次/pending并回读。SDK成功、历史写入、送达和已读分别表述。
5. 对已完整读取且已回复的入站消息，按[未读状态](../boss-recruiting-followup/references/unread-state.md)发送正常客户端已读回执并独立检查未读数。读取history或发出文字不等于完成此步；新入站或尚未处理的消息保留。已读回执失败单列，不改变真实发送结果，也不能因此重发文字。

不同目的确需两条时，各自审批/SHA/attempt/单次SDK/独立回读/CAS。第二条必须第一条确实成功后刷新本人完整history、绑定新CAS；不共用审批，不添无内容消息。入库后交接成功交[talent](../boss-recruiting-talent/SKILL.md)更新最后联系并再读回，才可进入已授权群推送。

结果未知或sender已调用后失败交[audit](../boss-recruiting-audit/SKILL.md)只读对账，不自动再调。输出真实发送/未发送、stage、mid与证据路径；本地拒绝不能冒称真实发送失败或候选人未回复。
