# 达标人才的群机器人推送

仅在用户指定群、机器人身份及人才推送用途后启用。候选人沟通仍只走BOSS；这是内部HR通知，不发邮件、不替代BOSS交接，不修改候选人的评分、轮次或最终联系时间。

## 配置与入口

工作区 `talent_push` 指向私有服务配置。群名/真实chat ID、应用机器人app ID/open ID、岗位、已授权run/scope、人才表、通知启用时刻、回执目录和鉴权token均存私有配置，不进skill或Git。

通过 `lark-im` / `lark-shared` 的CLI先精确查询群，验证内部群及机器人真实成员身份。发消息固定 `--as bot`；机器人不能读历史时，可以用户身份独立读回，但不能改成用户身份代发。消息采用结构化post文本节点和已验证的人才库链接；不发送互动卡片或大段简历，不发布电话、邮箱、年龄/性别、securityId、凭据或全文聊天。

实现入口：

- `scripts/talent_push.mjs`：资格检查、post正文及稳定防重键，纯函数不代替原始证据和实际读回。
- `scripts/talent_push_http.mjs`：鉴权、固定事件schema、大小限制和串行队列。
- `scripts/talent_push_server.mjs`：从既有正式记录、原始六项条件证据及最新人才表建立推送，不信任Webhook传来的分数或正文。
- `scripts/talent_push_client.mjs --config <私有服务配置> --drain`：完成入库、BOSS交接与最终联系读回之后，推送启用时刻之后的待通知记录。服务未启动时用隐藏后台Node进程按需启动；不重启BOSS或变更登录。

本地服务仅监听 `127.0.0.1`，使用强Bearer token。`POST /talent-screened` 接收 `type=talent.base_verified` 以及真实 `jobId`、`uid`、`recordId` 四个字段；不接受群ID、正文、地址或文件路径覆盖。`GET /health` 返回最小健康信息及无密钥的配置指纹，客户端必须核对指纹才能调用，配置路由变化需重启本服务。地址为本机入口，不能称为飞书自定义机器人的公网Webhook，也不自动开放公网。

## 推送门槛

1. 当前授权scope内，身份/岗位/正式record精确匹配，没有停联、重复暂停或需单独裁决的未发项。
2. 确定性基础>=60、覆盖>=70、信号>=65；正式初筛、岗位硬条件及本人AI编程实践已验收。引用既有通过证据，不为推送重算或抬分。
3. 六项现实条件的本人入站mid/原话核验通过；实际人才记录已创建、读回，BOSS真实交接和最终联系验收已完成。
4. 推送前新鲜读取人才表全部实际字段，核对姓名、岗位、UID/job依据、基础分/匹配分、AI通过及HR待复核，之后才发送。群名、ID、内部属性及机器人身份再次匹配。

写独占attempt之前再次检查live模式、工作区启用开关、全局及本人暂停项，并比对异步预检之前保存的正式记录、状态、scope和验收原件字节SHA。中途改变即停止，不能沿用旧资格发送。

正文说明“AI初筛通过，待HR复核；不代表面试或录用”。技术与项目指标标明候选人自述。院校仅作事实背景，不按院校档次筛选。链接使用已确认的人才库地址，不猜深链接参数。

## 防重与异常

防重键固定绑定 `(chatId, jobId, uid, recordId)`，资料补全、附件追加或分数展示更新不生成第二条推荐。发送前独占写attempt，使用同一Feishu idempotency key；完成后保存message ID和独立群回读。已成功事件直接返回duplicate，不再发送。

发送结果或读回未知时保留attempt/result，下一次触发也不发送。只读对账使用 `scripts/talent_push_client.mjs --config <配置> --uid <真实UID> --record-id <真实recordId> --reconcile`；或 `POST /talent-reconcile`。禁止自动重发、换key、换机器人/用户身份或删除旧回执。

CLI可能把post读回为格式化文本：核对完整文本与链接的精确投影、同message ID、目标群、机器人app/open ID，不能因不是原JSON就重发。不得仅凭发送命令退出成功声称群中已核验。

默认只推送启用后的新增达标记录；一次真实人选的联调须单独精确绑定。历史全量补推必须有用户明确范围，不能启用时自动刷旧名单。每轮招聘工作完成后检查待推送队列；无新增只保持静默。机器人权限或服务失败单独保存，不回滚人才记录或干扰BOSS已完成动作。
