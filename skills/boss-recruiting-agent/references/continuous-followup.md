# 持续招聘跟进

用于已获授权的定时轮询、当前岗位新招呼接续和真正漏回排查。发送、评分、账本与飞书操作仍分别遵循技术skill及本招聘skill的对应引用；本文补充长周期任务的接续规则。

## 规则与状态放置

- `SKILL.md` 和引用：可复用流程、证据判断、去重、发送与入库门禁。
- 私有任务入口：工作目录、岗位ID、运行目录、授权边界、已验收脚本和状态文件位置。
- 岗位资料与公司知识：仅当前岗位的已确认事实、用户来源及未知政策，不提升为所有岗位的通用政策。
- 正式候选记录、状态与回执：每人的分数、事实、轮次、待处理mid、真实发送/入库/交接状态及暂停裁决。
- `CONTINUE.md` 与批次验收：操作记录、异常解释和原始证据索引；不在每轮定时提示词中复制。

定时提示词只需说明目的、私有入口和关键用户限制。数字总量从最新验收读取，不在提示词手工维护。skill本身不构成新增联系人、发送或恢复暂停的授权。

## 开始一轮

1. 读取最新用户指示、任务入口、两类scope/manifest（如有）、状态和 `latestHeartbeat.source`。按需读最近一次CONTINUE段落，避免重新加载全部历史。检查已有待复核快照、代理产物、approval、attempt和回执，接续未完成阶段。
2. 检查任务约定的工作流锁及对应真实采集/发送进程。有活跃作业就避免并行；本次心跳自身active不是跳过理由。SDK读取、采集与发送由主代理串行执行。
3. 按授权范围采集。固定历史清单不改写；用户明确授权当前岗位后续新招呼时，用独立scope/ledger纳入、跨run按UID+job去重。姓名不同必须核同UID完整证据，不自动合并账号；保留历史回执中的原名。
4. 复用已验收的采集器。成功范围不重采；失败及未尝试只补相应UID并组合验收。未读到不能说没有回复，未尝试不能记成请求失败。短联系人页只能证明所见覆盖，不称服务端全量。

## 确定可执行入站

只处理真正新增、未处理的文本或已授权收到的简历文件，新增公司事实，或明确未完成的首轮任务。附件registry中的待复核正文属于新证据，不因聊天旧mid已处理而忽略；材料已复核或已挂表则不重复处理。

- 按 `(jobId, uid, mid)` 精确过滤已验收入站及 `no_reply_required`。未来新mid不能按UID跳过；出现新pending时移除失效marker，二者不可共存。
- 部分已审hold需要保留真实pending：以验收回执登记精确mid已处理，不为通过审计强清pending或伪造无需回复。
- 已问待答、感谢确认、已发送收尾不是漏回。只回复确有未回应问题或可执行新事实的会话，不因“已读”催促，不自动追加第三轮。
- 附件请求、图片、面试卡、撤回及收藏提示不当作条件接受、已收简历、面试已安排或真实HR交接。用户已授权附件接收时，另按 [简历附件流程](resume-attachments.md) 处理本人主动请求、邮箱收件和归档；没有授权时仅记录。撤回内容不推断，电话/微信交换不随附件授权一起同意。
- 不重分析已完成快照，不为静默轮询启动代理、重评分或改写全部账本。

## 离线复核与证据验收

按用户指定协作模型逐人复核。每名代理只拿本人岗位、正式record、完整history及必要引用，离线返回证据和草稿；不得读取别人资料或操作服务。基础全null在一次紧凑复核后跳过，不为填分深挖、补问或发拒绝。

主代理核真实源文件和本人 `from.uid`、mid、原话子串；接受证据必须来自候选人，招聘者问句只提供上下文。直接回答整组条件的合并“可以接受”可结合完整上下文，不要求机械逐项复述；指向不明的接受不能泛化。待遇或面试询问只有本人明确作为接受前提时才构成条件，不能自行增加门槛。

学校直接方便、允许外出或已有明确安排可作为可行证据；无课、离校、届别本身不能推出许可。保留本人到岗的面试/offer/手续前提，不把手续时长改到岗时长，不新增年份、证明完成或最晚到岗要求。卡片到岗核 `body.resume.applyStatus`、原mid、UID和job。

AI应用项目不自动证明AI辅助编程。工具使用有本人自述才确认该自述；具体深度另看实际环节。泛称学习快或列出技术不当学习协作证据。缺GitHub核查证据不能写成实际贡献为零。没有新技术不重算正式既有score/evaluation，只更新有来源的事实。

实际调用确定性评分器；基础、证明加分、信号和覆盖分开。R2与入库按岗位门禁校验（本仓库默认基础60、覆盖70、信号65）；任务已单独验收的真R0数值初评澄清策略仅在其授权scope和匹配源码下适用，不等于入库通过，不能伪造round0或抬分绕过后续门槛。

## 回复、发送与入库

自然短句，一条一个主要目的。顺着本人问题回应，不机械加“好的，了解了”或表情，不提前补发“整理一下”的空确认。R2只问缺项；已到两轮上限或 `next_round=0` 不问新的实质问题。

政策与真实HR交接保留实际轮次，不能借policy名义重问条件。不同目的需要两条时，每条独立approval、真实UTF8正文SHA、独占attempt、单次SDK、独立唯一新增回读及CAS；第二条必须第一条成功后刷新本人完整history并重绑真实CAS，不能将两条共用一次审批。

发送只走统一 `scripts/boss.mjs send`，可由已验收runner封装。核身份/job、完整history、job/profile SHA、原record CAS、正文SHA与双重发前校验。SDK1只证明一次调用；唯一新增出站证明历史写入，不能据此称已送达或已读。

入库必须能力门槛与岗位硬要求、所有必需现实条件明确通过；未知不能当不冲突即通过。飞书使用配置的用户身份、UID+job+姓名精确去重、dry-run、真实写入及当前schema全部字段读回HR待复核。实际成功后才自然交接，再更新最终联系时间并读回。已有HR按真实handoff状态核对，不重建或补发；既有记录身份核实不能冒称本轮新发送交接。新增材料可补原记录的附件，保留原轮次、评分和联系时间。

创建payload前按 [人才库字段规则](feishu-talent-base.md) 调用 `buildTalentCreateValues` 补原始资料可确认的年龄、性别、院校，保存证据和未知原因；不能继续沿用固定“写11项、略年龄性别”的历史构造器。院校评分无明确口径不填。15字段回读通过与实际填入多少项分别报告；已有记录补资料只作授权的局部维护，不重评、重发交接或修改最终联系时间。

## 暂停与本地失败

- 未知发送结果先只读对账，绝不自动重发、删除approval/attempt/result、改入口或换attempt绕过。
- 即使SDK未到，已登记 `blocked_*_no_send_do_not_retry` 或 `requiresSeparateExplicitDecision` 仍保持暂停，下一心跳、全局继续授权或新招呼授权均不解除；必须有单独明确裁决。
- 仅发生在sender子进程、SDK及正式CAS之前的本地草稿/hash/路径校验失败，在证明确无调用或写入后可保留原件、写v2修正；不要把已调用sender的失败当纯本地修改重进。
- 只读传输恢复按已验收白名单，最多一个新连接且只补失败范围；不重启客户端、改登录或猜根因。未保存的原响应/native错误不能事后编造。
- Base写入结果不明先查重/读回对账，不盲目重建。派生状态可从不可变证据恢复，正式账本必须CAS；不得用PowerShell大小写键转换覆盖Node JSON状态。

## 结束与下一轮

覆盖对账必须区分当前沟通列表、已跟进scope、正式候选账本和真实人才表；不能用waiting或单个run的数量代表当前岗位全部联系人。联系人页中落在历史账本、但不在现有collector范围的人仍要检查metadata是否推进；推进只产生待完整历史核实的线索，不等于真回复。用户已授权当前岗位持续跟进时，可将核实有新本人文本者登记为独立恢复范围，保留唯一正式记录、原轮次和历史基线，按已验收具名CAS链更新；不复制账号、悄悄并入旧冻结清单或重建已有人才。已处理的精确mid与成功读取截点需保存，未来新mid仍可接续。

校验本轮增量、回执前缀、scope、正式账本/索引、轮次、暂停项、原分保持和实际Base/交接状态。跨run旧基线有合法变化时只追加已验收的具名delta/hash链，不覆盖原始baseline、放宽sender或伪造hold绕过门禁。

将最新验收路径写入 `main-state.latestHeartbeat`，更新必要索引与CONTINUE；定时提示词继续使用稳定入口，无需每轮改写摘要。所有候选资料/凭据保存在受保护私有输出，不导出或提交Git。Windows新敏感目录先 `privateDirectory`，不修改旧目录ACL。

若工作区已启用 `talent_push`，完成真实入库、BOSS交接与最后联系读回后，按 [群推送流程](talent-group-push.md) 调用私有配置对应的 `talent_push_client.mjs --drain`。仅新增达标通知和真实未完成推送需要处理；已通知记录不因附件或资料补全再次推送。群通知异常保留独立回执，不回滚招聘动作或重发BOSS消息。

无变化或无可执行事项保持静默；只在实际回复/入库、完成、失败或确需用户信息时通知。全部对话及应入库核验完成后才停用心跳。
