# 批量采集和本地复核

当前Windows限定验证：20个同岗位联系人，正常在线简历结构化摘要与招呼已成功保存。全文未验证，不冒充附件PDF。

使用已确认的真实岗位JSON：

```powershell
node scripts/batch.mjs --job outputs/private/job.json --limit 20 --out outputs/batch-01
node scripts/batch.mjs --job outputs/private/job.json --limit 20 --out outputs/batch-02 --cache outputs/batch-01
```

输出必须是新目录。manifest.json 在批量读取前固定实际UID、姓名和岗位；records/保存最小专业资料，analysis.json是本地规则整理结果，report.html可离线复核，stats.json记录耗时、缓存及资料字节数。目录受Windows私有ACL保护，Mac文件使用0600；正常目录在任务开始预检一次，文件独占写入，不承诺对抗检查后外部改权限或替换目录。不得提交这些输出。

采集只连接一次，查询一次联系人，并逐人读取最多30条历史；只匹配当前可见UI与第一页联系人同UID/姓名/岗位，不滚动或自动翻页。正常点击姓名控件打开会话，再点在线简历，等待旧frame关闭和新getter初始化，每份摘要核对UID/姓名。打开会话可能改变我方已读状态。无发送、求简历、接受附件、交换联系方式或飞书写入。

采集期间临时关闭root及webview的后台渲染节流，结束时恢复并核对原值；正常关闭弹窗并恢复原选中会话，恢复失败明确报错。客户端进程和登录态保留。UI/身份变化、连续资料错误及未关闭frame会停止；已完成记录保留供新运行缓存复用，不伪造最终成功报告。

缓存按UID/姓名/岗位、招呼内容指纹及最长24小时有效期复用摘要，每次仍读新历史。损坏或条目形状错误的缓存重新采集；缓存命中不证明候选人在期间没有修改在线简历，有新核实需求时不传cache。

规则只分组和提取项目/技术线索，不把关键词直接变能力分或录用结论。主代理对紧凑资料做一次复核，明确说明自述、未知项与优先沟通理由；已有出站、停止请求或不完整历史不进入自动开场建议。实习生了解技术、工具、本人功能和独立能力，再按评分规则记录基础分与竞赛加分；不要求验证代码。首次统一“你好”开场。

复核评分结果中能力基础分仍为“待了解”（`abilityBaseScore=null`）的，本轮直接跳过，不再补问、深挖或另派Agent；保留null和本地跳过原因，不发送拒绝通知。基础分已有数值而部分维度未知的继续正常筛选，比赛加分不能填补未知基础分。采集器 `analysis.abilityScore` 固定为null表示尚未评分，不能据此把整批候选人全跳过。

采集清单不授权群发。后续沟通先形成具体收件人清单和各自草稿，逐人读取最新完整历史，使用既有boss.mjs send的授权/哈希/锁/attempt与唯一新增回读检查，不复用过期指纹。用户要求先看模拟话术时，等待其确认后再发送新口径消息。
